# v0.6.0 — output contracts, audit triad, dispatcher removal, runtime enforcement

This release completes the governance-design optimization that started
with [the v0.6.0 optimization roadmap](https://github.com/rootazero/pi-rolecast/blob/main/references/v0.6.0-optimization-roadmap.md).
It is **additive** on top of v0.5.x: every existing v0.5.x profile
keeps loading, and the only breaking change is the optional removal
of `coding-orchestrator` (per ADR-0010's "no central orchestrator"
principle).

**TL;DR**
- `Profile.contracts` — per-role output JSON Schemas, validated at scaffold time (A1).
- `allowed_tools` + `forbidden_bash_patterns` — declared on the role's
  frontmatter, surfaced in the generated agent file **and at the runtime
  tool-call hook** (A2 / A5 + D1).
- `soul` — every audit-tier role ships with `souls/audit-law.md` (A3).
- Audit triad — `coding-judge`, `coding-countersign`,
  `coding-notary`, `coding-secretariat` (B1).
- Worker split — `coding-coder` (plan + apply) and `coding-fixer`
  (finalize) (B2).
- `coding-orchestrator` removed (per ADR-0010) (C1).
- `coding-diarist` (renamed from `coding-docs`) (C2).
- `gate_runner.audit_roles` typo-safety — unresolved audit roles fail
  the phase even when shell commands succeed (D2).
- `docs/profile-schema.md` — 16 KB standalone schema reference (D3).
- Legacy-name dispatch lookup — `subagent_type: coding-implementer`
  still resolves after the rename.

**202 / 202 unit tests passing.** `npm run typecheck` clean.

## What you have to change to v0.6.0

### Nothing, if you write new profiles

The framework ships with new active role names already wired into all
six starter templates (`rust`, `typescript`, `python`, `go`,
`javascript`, `blank`). New profiles don't need any migration — just
pick a template and `pi-rolecast init`.

### One line per binding, if you have an existing v0.5.x profile

`profiles`:

```yaml
# v0.5.x
bindings:
  coding-implementer: {alias: deepseek-verifiable, channels: [official]}
  coding-reviewer:    {alias: gpt-judgment-high,   channels: [official]}
  coding-docs:        {alias: minimax-medium,      channels: [official]}
  coding-orchestrator: {alias: gpt-judgment-medium, channels: [official]}
```

```yaml
# v0.6.0 (post-migration; same effect, current names)
bindings:
  coding-coder:    {alias: deepseek-verifiable, channels: [official]}
  coding-judge:    {alias: gpt-judgment-high,   channels: [official]}
  coding-diarist:  {alias: minimax-medium,      channels: [official]}
  # coding-orchestrator removed — caller dispatches via the Agent tool.
```

Or just leave the old names: the `LEGACY_ROLE_ALIASES` table rewrites
them for one release with a `DEPRECATED` warning on
`profile.load_warnings`. `coding-orchestrator` is dropped with a
louder `REMOVED` warning. v0.7.0 removes the alias table.

### Optional: opt into the audit triad

The audit triad and `coding-fixer` are **opt-in** in v0.6.0. Add them
to `bindings:` when you want them. They ship with the canonical
`allowed_tools: [read, grep, find, ls]` and
`forbidden_bash_patterns: ["rm -rf", "git reset --hard", "git clean",
"git checkout --"]` from the ak prompt's `code-style`.

## A套 — output contracts + toolset narrowing

### A1: `Profile.contracts`

Profiles can declare per-role output JSON Schemas under a top-level
`contracts:` mapping. The scaffold validator
(`scaffolder validate`) calls `validateAllContracts` from
`src/contracts.ts` and reports any malformed schemas or unknown
role names.

v0.6.0 enforces **structural** validation. Adherence at runtime
(whether the LLM actually returned a payload matching the schema)
is the caller's responsibility; `checkContractPayload(role,
payload)` is exported from `src/contracts.ts` so workflow tooling can
opt in.

### A2: `allowed_tools` (declarative + runtime hook)

Role files may declare a narrowed toolset:

```yaml
allowed_tools: [read, grep, find, ls]   # e.g. coding-notary
```

`sync_settings` writes a `Tool restrictions` block into the generated
agent file. **In v0.6.0, the framework enforces it**: when the role is
the most recently invoked `Agent`, the tool_call hook calls
`enforceRoleNarrowing(event, bindings, currentRole)` on every
subsequent non-Agent tool call. Calls outside the list are blocked
with a reason string. See `docs/profile-schema.md` §4.5.

### A3: `soul` layering

Role files may reference a shared "soul" markdown:

```yaml
soul: ../souls/coding/_common.md   # relative from role file
```

The generator prepends the soul content after the frontmatter,
bracketed by HTML-comment markers
`<!-- soul-do-not-edit:start -->` /
`<!-- soul-do-not-edit:end -->`.
This implements ADR-0005: soul is the generic-law; the role body is
the host overlay.

`souls/audit-law.md` ships as the canonical soul for audit-triad
roles. Editing it changes the voice for every audit-tier dispatch at
once.

### A4: `audit_max_resubmits`

`escalation.audit_max_resubmits: number | null` (default `null` =
unbounded per ADR-0007). The scaffold validator prints the value (or
`unbounded`) in its summary. v0.7.x will wire it into the gate
runner runner-side enforcement.

### A5: `forbidden_bash_patterns` (bash seatbelt)

Role files may declare forbidden bash substrings:

```yaml
forbidden_bash_patterns:
  - "rm -rf"
  - "git reset --hard"
  - "git clean"
  - "git checkout --"
```

`sync_settings` writes a `Bash seatbelt` block listing these patterns,
with the caveat *防呆不防坏* — "guards against accidents, not malice".
**In v0.6.0, the framework enforces it**: when the role is the most
recently invoked `Agent` and the active tool is `bash`, the
seatbelt inspects the bash payload (trying keys `command`, `cmd`,
`script` in that order) for any forbidden substring and blocks the
call on a hit.

The canonical four ship on `coding-coder` and `coding-fixer`. Other
roles inherit the seatbelt via `coding-fixer`'s bash surface.

## B套 — audit triad + worker split

### B1: audit triad (per ADR-0032)

Four new role files in `role-packs/coding/`:

- **`coding-judge`** — verdict seat; primary auditor; emits
  `GATES_GREEN` / `NEEDS_REWORK` / `SEATBELT_HIT`. Strong tier
  (`gpt-judgment-high`).
- **`coding-countersign`** — adversarial second pair of eyes; tries
  to refute the judge's verdict; either confirms or raises a
  counter-finding. Strong tier (`opus-thinking-high`).
- **`coding-notary`** — evidence collector; pulls exact passages,
  line numbers, test outputs, command results. Read-only — no bash.
  Cheap tier.
- **`coding-secretariat`** — audit log recorder; writes findings to a
  durable record. Opt-in. Cheap tier.

All four bind the audit-law soul and the four canonical forbidden
bash substrings.

### B2: worker split (per ADR-0034)

The old `coding-implementer` is replaced by:

- **`coding-coder`** — two-phase worker (`plan` and `apply`). The
  dispatcher passes one phase per dispatch; coder refuses if neither
  is set. Balanced tier (`deepseek-verifiable`).
- **`coding-fixer`** — finalization phase (`finalize`). Runs gates,
  fixes the easy red, hands off the hard red. The bash seatbelt
  role. Balanced tier.

Old `coding-implementer` is preserved with
`deprecated_redirect: coding-coder` for one release.

## C套 — dispatcher removal + diarist rename

### C1: `coding-orchestrator` deprecated (per ADR-0010)

The dispatcher logic moves to the caller. **There is no replacement
role.** The file is preserved for one release with
`deprecated_redirect: null` so users with old profiles see a
`REMOVED` warning instead of a hard error. Profiles declaring a
binding for it get the binding dropped on load.

### C2: `coding-diarist` (renamed from `coding-docs`)

"Diarist" matches ak semantics: it records findings for human
readers. Allows `write` / `edit` but excludes `bash`. Old `coding-docs`
is preserved with `deprecated_redirect: coding-diarist` for one
release.

## D套 — runtime enforcement + schema reference

### D1: extension tool_call hook

`src/extension.ts` now exports `enforceRoleNarrowing(event,
bindings, currentRole)`, a pure decision helper. The Agent branch
of the `tool_call` hook records `currentRole` after a successful
dispatch; the non-Agent branch consults the helper to block calls
outside `allowed_tools` or commands matching
`forbidden_bash_patterns`. Pure function, exported, covered by 11
unit tests in `tests/unit/test_runtime_hook.ts`.

### D2: gate_runner audit-role typo-safety

`GateDef.audit_roles?: string[]` is a new optional field. The
runner validates every declared audit role against `profile.
resolved_bindings` and surfaces unresolved roles on the phase
result. A phase with unresolved audit roles **fails even when shell
commands succeed** — this catches stale role references at
config-validation time rather than at audit-time.

Real LLM-driven audit invocation remains the profile author's
responsibility (via the `commands:` field). The framework cannot
dispatch sub-agents from the gate runner itself; `audit_roles` is a
declarative + typo-safety surface only.

### D3: schema reference doc

`docs/profile-schema.md` (16 KB) is the canonical v0.6.0 schema
reference. 13 sections covering profile top-level fields, bindings,
contracts, role-pack frontmatter (including `allowed_tools` /
`soul` / `forbidden_bash_patterns` / `phase_inputs` /
`deprecated_redirect`), `LEGACY_ROLE_ALIASES` behaviour, gates,
non-negotiables, escalation, custom roles, workflow / role-groups,
contracts, runtime enforcement, required minimum, versioning.

## Migration guide (one paragraph)

`LEGACY_ROLE_ALIASES` is the safety net for v0.6.0. Old binding keys
(`coding-implementer`, `coding-reviewer`, `coding-docs`) keep
working for one release with a `DEPRECATED` warning surfaced in
`scaffolder validate` and via `dumpBindings`. `coding-orchestrator`
binding keys are dropped with a louder `REMOVED` warning. The
`resolveLegacyRoleName(name, bindings)` helper in
`src/dump_bindings.ts` is wired into the `tool_call` hook so legacy
names in `subagent_type` continue to resolve at dispatch time.
**v0.7.0 removes the alias table**; profiles must use the current
names.
