# pi-rolecast v0.7.0 — audit_workflow + LEGACY_ROLE_ALIASES removal

> Released 2026-10-08

## TL;DR

- **`LEGACY_ROLE_ALIASES` rewrite shim removed.** Profiles still using
  `coding-implementer` / `coding-reviewer` / `coding-docs` /
  `coding-orchestrator` now hard-fail at load time with a clear
  migration hint.
- **`audit_workflow.ts` runtime helpers** — the
  `Escalation.audit_max_resubmits` knob shipped in v0.6.0 now has a
  pure-function runtime counterpart that workflow callers can use
  to honor the cap.
- **`Escalation` validator hardening** — all four numeric knobs now
  reject fractional / negative / non-number values at load time
  through a shared `parseNonNegIntOrNull` helper. Two new knobs:
  `gate_max_attempts` and `non_negotiable_max_retries`.

## Summary

This release finishes the three items deferred from v0.6.0. They are
small but each closes a follow-up that produced loud comments on the
v0.6.0 changelog. Profile authors on the new v0.6.0 names see no
behavior change; profile authors on v0.5.x or earlier names see a
deliberate, actionable error rather than a silent alias rewrite.

## E1 — `Escalation` validator hardening

`Escalation` had three numeric knobs in v0.6.0 (`max_attempts`,
`audit_max_resubmits`, plus the existing ones) with inconsistent
validation. v0.7.0 routes all four through one helper and adds two
new caps.

```yaml
escalation:
  max_attempts:                2    # per-phase retry cap
  gate_max_attempts:           6    # NEW — session-level cap, summed across phases
  audit_max_resubmits:         2    # cap on audit-rejected resubmits (v0.6.0)
  non_negotiable_max_retries:  1    # NEW — cap on non-negotiable violations
  on_permanent_failure:     stop    # stop | continue
  preserve_logs:            true    # boolean
```

`parseNonNegIntOrNull(raw, fieldPath)` is the single chokepoint. It
throws `ProfileError` (with the dotted field path) on:

- non-number values
- fractional values
- negative values
- anything that is not an integer or the literal `null`

The `null` case stays open — `null` means *unbounded* and is the
default for all four knobs.

`validateProfile` now prints a compact one-line summary:

```
escalation: max_attempts=2, gate_max_attempts=6, audit_max_resubmits=2,
            non_negotiable_max_retries=1, on_permanent_failure=stop,
            preserve_logs=true
```

If a knob is `null`, the line shows `unbounded` instead of `0`.

## E2 — `audit_workflow.ts` runtime helpers

`Escalation.audit_max_resubmits` shipped in v0.6.0 with a structural
declaration but no runtime counterpart. v0.7.0 ships
`src/audit_workflow.ts` — a tiny pure-function module that workflow
callers can use to honor the cap without rolling their own counter.

```typescript
import {
    readAuditCounter,
    incrementAuditCounter,
    canResubmit,
    resetAuditCounter,
} from "pi-rolecast/dist/audit_workflow.js";

const verdict = canResubmit(profile.escalation, logDir);
if (!verdict.allowed) {
    throw new Error(
        `audit cap exhausted after ${verdict.attempt} of `
        + `${profile.escalation.audit_max_resubmits}`,
    );
}
incrementAuditCounter(logDir);
// dispatch the coder/fixer...
```

| Export | Signature | Notes |
|---|---|---|
| `readAuditCounter(logDir)` | `(string) => number` | `0` on missing file. Pure read. |
| `incrementAuditCounter(logDir)` | `(string) => number` | Writes + returns post-increment. |
| `canResubmit(escalation, logDir)` | `(Escalation, string) => ResubmitVerdict` | Pure read — does not mutate. |
| `resetAuditCounter(logDir)` | `(string) => void` | No-op when file is absent. |
| `interface ResubmitVerdict` | `{ allowed: boolean, attempt: number, max: number \| null, remaining: number \| null }` | Plain object, JSON-safe. |

Persistence is `logDir/counters/audit-counter.json` holding
`{ "audit_attempt": number }`. Writes are atomic (tmp + rename) so
two concurrent readers never see a partial JSON document.

22 unit tests cover the four exports, the loop pattern (start at
zero, increment, cap, reset, repeat), and the atomic-write invariants
(no `.tmp` leftovers, parses the `audit_attempt` key on reload).

## E3 — `LEGACY_ROLE_ALIASES` removal

v0.6.0 introduced a small forward-reference guard in `parseProfile`
that rewrote legacy names at load time and emitted a `DEPRECATED`
warning. That shim is now removed. Old names fail loudly with a
specific migration hint.

| Legacy name | New name | Migration hint |
|---|---|---|
| `coding-implementer` | `coding-coder` | "renamed to `coding-coder` in v0.6.0" |
| `coding-reviewer` | `coding-judge` | "renamed to `coding-judge` in v0.6.0" |
| `coding-docs` | `coding-diarist` | "renamed to `coding-diarist` in v0.6.0" |
| `coding-orchestrator` | *(removed)* | "REMOVED in v0.6.0 per ADR-0010 — caller dispatches directly" |

The hint fires in two places:

1. **Profile load** (`parseBindings`): when a bindings key is not in
   any enabled role group and not in `custom_roles`, the parser looks
   the name up in `LEGACY_ROLE_REDIRECTS` (the new internal table
   that's keyed on legacy names only). A hit emits a
   `ProfileError` with the migration hint.
2. **Runtime dispatch** (`src/extension.ts` `tool_call` hook): when
   an at-handle reaches the dispatcher with a legacy name, the hook
   blocks the dispatch and returns the same hint.

The four legacy role-pack markdown files ship on disk for one
release (`v0.7.x`) with `deprecated_redirect` in frontmatter, so
they're skipped at discovery time but still discoverable for
profiling users who want to see the migration trail. `v0.8.x` will
delete them outright.

`coding-reviewer.md` had been missing the `deprecated_redirect`
field — v0.7.0 adds `coding-judge` so the legacy skip path is
uniform across all four files.

## Migration guide (v0.6.0 → v0.7.0)

1. Open your `.pi/rolecast.yaml` bindings and rename:
   - `coding-implementer` → `coding-coder`
   - `coding-reviewer` → `coding-judge`
   - `coding-docs` → `coding-diarist`
   - `coding-orchestrator` — *remove the line entirely*
2. Same for `contracts:` declarations if you declared any.
3. Add `escalation.gate_max_attempts` and
   `escalation.non_negotiable_max_retries` if you want explicit caps;
   leave unset (`null`) for unbounded.
4. If you wrote a workflow orchestrator that retries on audit
   rejection, import the helpers from
   `pi-rolecast/dist/audit_workflow.js` and call `canResubmit` +
   `incrementAuditCounter` instead of rolling your own counter.

After updating, run `npx pi-rolecast rolecast-validate` and verify
the escalation summary line shows your six fields.

Profiles that don't reference any legacy role names work unchanged.

## What's deferred to v0.8.x

- Hard-delete the four `coding-<legacy>.md` role-pack files.
- Per-role `allowed_tools` runtime enforcement — currently the
  framework writes the *declaration* into the generated
  `.pi/agents/<role>.md` but the dispatcher does not block tools at
  runtime. `src/extension.ts` exposes `enforceRoleNarrowing` as a
  helper; wiring it into the tool-call hook is the remaining
  surface.
- `gate_runner` audit-phase enforcement — the `audit_roles` field
  ships in v0.6.0; the runtime branch that dispatches the audit
  triad after a phase goes red is not yet wired.
