# v0.7.0 optimization roadmap — design-of-record

> Status: design-of-record.
> Author: pi-rolecast maintainers.
> Predecessor: [`v0.6.0 optimization roadmap`](./v0.6.0-optimization-roadmap.md).

## Why

v0.6.0 shipped the framework surface (A套) plus the role rename /
audit triad (B) plus dispatcher removal (C) plus runtime enforcement
(D). Three items were explicitly deferred to "v0.7.x" in the v0.6.0
changelog:

1. `escalation.audit_max_resubmits` had a validator but no enforcement
   surface. Workflow callers had to roll their own counter logic.
2. The `LEGACY_ROLE_ALIASES` table was kept for one release as a
   migration aid. v0.7.0 removes it cleanly.
3. `parseEscalation` only validated `audit_max_resubmits`. The other
   numeric knobs (`max_attempts`, `preserve_logs`) were silently
   coerced; bad form types passed.

In addition, the user requested an "escaper validator" (interpreted
in this roadmap as "escalation validator hardening" — see ADR-0010).

This roadmap covers three phases, all additive or clean-removal. **No
new role files.** **No schema-incompatible profile changes** beyond
the explicit LEGACY_ROLE_ALIASES removal.

## Detailed design

### E1 — `parseEscalation` validator hardening

**Schema change** (`src/profile_loader.ts` `interface Escalation`):

```ts
export interface Escalation {
    max_attempts: number;                              // existing
    on_permanent_failure: "stop" | "continue";        // existing
    preserve_logs: boolean;                            // existing
    audit_max_resubmits: number | null;                // existing (v0.6.0)

    // v0.7.0 (E1.1) — session-level gate-attempt ceiling.
    // `null` (default) = unbounded, matches v0.6.0 semantics.
    // Distinct from per-phase `max_attempts` in PhaseDef.
    gate_max_attempts: number | null;

    // v0.7.0 (E1.2) — cap on consecutive non_negotiable violations
    // before the gate runner hard-fails. `null` (default) = unbounded.
    non_negotiable_max_retries: number | null;
}
```

**Validator behaviour**:

```ts
// Existing
if ("audit_max_resubmits" in obj && obj["audit_max_resubmits"] !== null) { ... }

// New (E1.3) — same shape applied to all numeric fields
function requireNonNegIntOrNull(raw: unknown, fieldPath: string): number | null {
    if (raw === null) return null;
    if (typeof raw !== "number" || !Number.isInteger(raw) || raw < 0) {
        throw new ProfileError(
            `${fieldPath} must be a non-negative integer or null`,
        );
    }
    return raw;
}
```

**Scaffold reporting**: `validateProfile` prints the new fields in
the same summary line as `audit_max_resubmits`:

```
escalation: max_attempts=2, gate_max_attempts=unbounded,
           audit_max_resubmits=unbounded,
           non_negotiable_max_retries=unbounded,
           on_permanent_failure=stop, preserve_logs=true
```

### E2 — `src/audit_workflow.ts` (new module)

**Public surface** (all pure functions, zero external deps):

```ts
import type { Escalation } from "./profile_loader.js";

export interface ResubmitVerdict {
    allowed: boolean;
    /** 0-indexed attempt count after the most recent increment. */
    attempt: number;
    /** `null` if no cap declared. */
    max: number | null;
    /** `max - attempt` if max declared; `null` if unbounded. */
    remaining: number | null;
}

export function readAuditCounter(logDir: string): number;
export function incrementAuditCounter(logDir: string): number;
export function canResubmit(escalation: Escalation, logDir: string): ResubmitVerdict;
export function resetAuditCounter(logDir: string): void;
```

**Persistence format**: `logDir/counters/audit-counter.json`,
JSON `{ "audit_attempt": number }`. Atomic write via `fs.writeFile`
to a tmp file then rename. Counter starts at 0; first
`incrementAuditCounter` returns 1; `canResubmit` checks
`attempt < max` (or `attempt < Infinity` if `null`).

**Caller pattern**:

```ts
// After every audit-triad verdict (e.g. `NEEDS_REWORK`):
import { canResubmit, incrementAuditCounter } from "pi-rolecast/dist/audit_workflow.js";

const verdict = canResubmit(profile.escalation, logDir);
if (!verdict.allowed) {
    throw new Error(`Audit cap exhausted after ${verdict.attempt} of ${profile.escalation.audit_max_resubmits}`);
}
incrementAuditCounter(logDir);
// Resubmit the work to the coder/fixer.
```

**No wiring into the gate runner** — `audit_max_resubmits` is a
workflow-level concept (ADR-0007: "no auto-retry on audit
rejections"). The gate runner only validates the *declaration* via
`audit_roles`; the actual resubmit loop is the caller's
responsibility.

### E3 — Remove `LEGACY_ROLE_ALIASES`

**Delete**:
- `export const LEGACY_ROLE_ALIASES` (profile_loader.ts ~line 208)
- `LEGACY_ROLE_ALIASES` lookup inside `parseBindingsWithLegacyRewrite`
- `export function resolveLegacyRoleName` (dump_bindings.ts)
- Legacy-rewrite branch in `src/extension.ts` tool_call Agent branch

**Rename** `parseBindingsWithLegacyRewrite` → `parseBindings`.
This makes the legacy-removal change visible at every call site.

**Migration error**:

```ts
function parseBindings(raw: unknown, allowedRoles: Set<string>, packs: Record<string, RoleDef>): Record<string, BindingDef> {
    for (const role of Object.keys(raw)) {
        if (!allowedRoles.has(role) && !packs[role]) {
            throw new ProfileError(
                `bindings.${role} is not in any enabled role group and is not declared in custom_roles. ` +
                `In v0.7.0 the LEGACY_ROLE_ALIASES migration table has been removed. ` +
                `Rename to the current role name — see CHANGELOG.md v0.6.0 "Migration guide" or ` +
                `docs/profile-schema.md §6 (Migration).`,
            );
        }
    }
    // ...
}
```

**Affected role names**: `coding-implementer`, `coding-reviewer`,
`coding-docs`, `coding-orchestrator`. Profiles declaring these will
fail at scaffold-validate time with a clear migration message.

**Affected tests** (to be updated):
- `tests/unit/test_profile_loader.ts` — ~22 tests reference the
  rewrite table. Replace with end-to-end "current name passes, legacy
  name produces migration error".
- `tests/unit/test_dump_bindings.ts` — delete the 5
  `resolveLegacyRoleName` tests.
- `tests/integration/test_dynamic_binding_smoke.ts` — replace legacy
  dispatch with current-name dispatch.

## Acceptance criteria

- **E1**: `npm test` covers `parseEscalation` rejecting negative,
  non-integer, non-null values for all five numeric fields
  (`max_attempts`, `gate_max_attempts`, `audit_max_resubmits`,
  `non_negotiable_max_retries`, plus existing). Scaffold
  `validateProfile` prints the new fields. Typecheck clean.
- **E2**: `tests/unit/test_audit_workflow.ts` covers
  `readAuditCounter` (0 on missing file), `incrementAuditCounter`
  (returns monotonic sequence), `canResubmit` (allowed when null,
  allowed when attempt < max, blocked when attempt >= max),
  `resetAuditCounter` (removes file). Pure-function tests.
- **E3**: `npm test` covers legacy-name binding producing the new
  migration error. Existing end-to-end tests pass with current names.
  Grep for `LEGACY_ROLE_ALIASES` returns no results in src/ or
  tests/ except possibly a comment in CHANGELOG.
- **Phase 4**: `npm test` 202/202+ green. `npm run typecheck` clean.
  Manual smoke: `npm view pi-rolecast@0.7.0` shows the package live.

## Out of scope (deferred to v0.8.x)

- **Per-phase max_attempts as a Profile top-level override** —
  currently `PhaseDef.max_attempts` overrides `Escalation.max_attempts`
  only when explicitly declared. v0.8.x could surface a per-phase
  cap distinct from the gate-wide one.
- **Audit verdict caching** — currently `audit-counter.json` only
  tracks the count, not the actual verdict history. v0.8.x could
  persist a verdict ledger` at `log_dir/counters/audit-ledger.jsonl`
  so post-mortem can replay the audit chain.
- **`escalation.audit_max_resubmits` enforcement inside the gate
  runner** — would require the gate runner to dispatch sub-agents,
  which it currently doesn't. v0.8.x might add a `gate_runner
  audit-phase` mode that dispatches audit roles and enforces the
  cap in-process.

## Versioning

- **Semver**: 0.6.0 → 0.7.0 (minor, NOT major — backward-incompatible
  changes are restricted to LEGACY_ROLE_ALIASES users, who were
  warned in v0.6.0).
- **Tag**: `v0.7.0` follows the existing `v*.*.*` pattern; CI
  release workflow picks it up automatically via `release.yml`.
- **npm**: `dist-tags.latest` moves from 0.6.0 → 0.7.0.
