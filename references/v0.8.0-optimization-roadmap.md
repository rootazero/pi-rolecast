# v0.8.0 optimization roadmap

Status: draft — design-of-record. Scope = the three items deferred from
v0.7.0. Time horizon: one release cycle.

## Why

The v0.7.0 release closed three deferred items (E1/E2/E3). It also
named three follow-ups in the [What's deferred to v0.8.x] section of
the v0.7.0 release notes:

1. **Hard-delete the four legacy role-pack files** that ship on disk
   for one release (`coding-implementer.md`, `coding-reviewer.md`,
   `coding-docs.md`, `coding-orchestrator.md`).
2. **Confirm `enforceRoleNarrowing` actually fires in production**
   — the deferred note said "wiring it into the tool-call hook is the
   remaining surface", but the wiring landed in v0.6.0 D-slot. Audit +
   close out, or add the missing piece if one turns up.
3. **Wire `audit_roles` dispatch into the gate runner** so a phase
   can declare an audit triad that the runner orchestrates (instead of
   the v0.6.0 D-slot's pure unresolved-binding sanity check).

Each item is independent. Slots ship separately so any one can be
cut without breaking the others.

## Detailed design

### F1 — hard-delete the four legacy role-pack files

The `deprecated_redirect` skip path was v0.7.0's transitional tool.
v0.8.0 retires it.

```text
git rm role-packs/coding/coding-implementer.md
git rm role-packs/coding/coding-reviewer.md
git rm role-packs/coding/coding-docs.md
git rm role-packs/coding/coding-orchestrator.md
```

Then in `src/profile_loader.ts`:

- Delete `LEGACY_ROLE_REDIRECTS` const.
- Delete the `deprecated_redirect` skip clause in `discoverRolePacks`.
- In `parseBindings` and the contracts-name check inside
  `parseProfile`, the legacy-lookup branches become hard errors
  with a sharper message: "v0.8.0: the role '<name>' has been
  removed. See references/v0.6.0-optimization-roadmap.md for the
  v0.5.x → v0.8.x rename table."

In `src/extension.ts`:

- Delete the legacy-redirect consult branch in the tool_call hook.
  Profiles that still try to dispatch via at-handle or subagent_type
  with a legacy name now fail with the same migration hint, but the
  failure happens earlier (at dispatch time) instead of during
  profile load.

In `src/dump_bindings.ts`:

- No change — the v0.7.0 cleanup already deleted
  `resolveLegacyRoleName`.

Tests:

- `tests/unit/test_profile_loader.ts`:
  - Delete the 6 v0.7.0 migration tests (replaced by a single
    hard-error test).
  - Add 1 test: "v0.8.0: legacy binding for coding-implementer
    throws a hard ProfileError without LEGACY_ROLE_REDIRECTS lookup".
- `tests/unit/test_dynamic_binding_smoke.ts`: no change (already
  uses new active names).
- `tests/unit/test_scaffolder.ts`: confirm sample-rust still passes
  without REMOVED-warning logic (it should, since the warning was
  removed in v0.7.0).

### F2 — audit role narrowing runtime coverage

The runtime enforcement already works in v0.7.0 (`enforceRoleNarrowing`
is called from the tool_call hook at `extension.ts:923`, and
`BindingPayload.allowed_tools` is populated by `dumpBindings` at
`dump_bindings.ts:75`). The deferred note was stale.

What v0.8.0 actually does:

- Add 3 integration-style tests in `tests/unit/test_runtime_hook.ts`
  that exercise the runtime path end-to-end:
  1. **Fresh session has unrestricted `currentRole`.** Before any
     Agent dispatch, `currentRole === null`, so
     `enforceRoleNarrowing` returns `undefined` and the tool call
     proceeds.
  2. **Agent dispatch sets `currentRole` to the dispatched
     subagent_type.** After a successful Agent tool call, the
     module-level `currentRole` equals the dispatched role.
  3. **Sequential dispatches track the last one.** Two back-to-back
     Agent dispatches leave `currentRole` pointing at the second
     dispatched role (documents the "parallel subagents inherit the
     last role" limitation already noted at
     `extension.ts:474-483`).

No source change to `extension.ts` itself.

### F3 — audit dispatch helpers

The v0.6.0 D-slot introduced `audit_roles` on `GateDef` and
`resolveAuditRoles` in `gate_runner.ts`. The behavior is a pure
unresolved-binding sanity check — the gate runner does NOT actually
dispatch the audit roles. Per ADR-0010, the framework does not spawn
subagents (composition is the caller's responsibility); what the
framework CAN do is hand the caller a clean dispatch plan and accept
post-dispatch verdicts back.

What v0.8.0 adds:

```typescript
// src/audit_workflow.ts (new exports)
export interface AuditDispatch {
    role: string;          // role-pack name (e.g. "coding-judge")
    alias: string;         // resolved model alias from bindings
    channels: string[];    // binding channels
    fallback_chain: string[]; // binding fallback chain
}

export function resolveAuditDispatchPlan(
    profile: { gates: Record<string, GateDef>; resolved_bindings: Record<string, BindingPayload> },
    phaseName: string,
): { phase: string; dispatch: AuditDispatch[]; unresolved: string[] };

export function recordAuditVerdict(
    logDir: string,
    role: string,
    verdict: "approved" | "needs_rework" | "rejected",
): { attempt: number; capReached: boolean };
```

`resolveAuditDispatchPlan`:

- Reads `profile.gates[phaseName].audit_roles` (defaults to `[]`).
- For each role name, looks up `resolved_bindings[role]` and emits
  an `AuditDispatch`.
- Roles that don't resolve accumulate into `unresolved`.
- Pure read — no side effects.

`recordAuditVerdict`:

- Increments the audit counter (via `incrementAuditCounter`) when
  the verdict is `needs_rework` or `rejected`.
- Does NOT increment on `approved` (one approval closes the audit
  loop for the current attempt).
- Returns `{ attempt, capReached }` from the existing `canResubmit`
  helper, so the caller knows whether the gate runner should accept
  another attempt or fail the phase.

In `src/gate_runner.ts`:

- `PhaseResult` interface gains `audit_required?: boolean` and
  `audit_plan?: AuditDispatch[]`.
- `runPhase` reads `<runDir>/audit-verdicts.json` (a `{role: verdict}`
  map) BEFORE running the commands. If present and any verdict is
  `needs_rework` / `rejected`, the phase is treated as FAIL with
  `audit_resubmit: true` in `last_failure.reason`. `canResubmit` is
  consulted; when the cap is reached, the phase fails permanently
  with `audit_resubmit: false` and the escalation policy decides
  whether to stop or continue.
- `runPhase` always emits `audit_required: auditRoles.length > 0`
  and `audit_plan: resolveAuditDispatchPlan(...)` on the result.

Tests:

- `tests/unit/test_audit_workflow.ts`: 6 new cases covering
  `resolveAuditDispatchPlan` (happy path, unresolved role, empty
  audit_roles, missing phase) and `recordAuditVerdict` (approved
  doesn't increment, needs_rework increments, rejected increments,
  cap-reached).
- `tests/unit/test_gate_runner.ts`: 4 new cases covering
  pre-existing audit-verdicts file (approved → pass,
  needs_rework → fail with resubmit), cap-exhausted (fail with no
  resubmit), and the new `audit_required` / `audit_plan` emission.

## Acceptance criteria

- 246+ tests passing (235 baseline + 3 F2 + 6 F3 audit_workflow + 4
  F3 gate_runner = 248 expected).
- typecheck clean.
- The four legacy role-pack files are gone from `git ls-files`.
- `LEGACY_ROLE_REDIRECTS` and `parseBindingsWithLegacyRewrite` are
  gone from the source tree.
- `audit_workflow.ts` exports `resolveAuditDispatchPlan` and
  `recordAuditVerdict`.
- `gate_runner.ts` `PhaseResult` has `audit_required` and
  `audit_plan` fields, populated by `runPhase`.
- A profile with `audit_roles: [coding-judge]` and a
  `<runDir>/audit-verdicts.json` containing
  `{ "coding-judge": "needs_rework" }` causes the gate phase to
  FAIL with `audit_resubmit: true`; after `escalation.audit_max_resubmits`
  resubmits, the phase fails permanently with `audit_resubmit: false`.

## Out of scope (for v0.8.x and beyond)

- Auto-dispatching the audit triad from within the gate runner
  (would require an in-process subagent spawn, which the framework
  does not own per ADR-0010). The dispatch plan + verdict feedback
  loop keeps the framework out of that business.
- Renaming `escalation.audit_max_resubmits` to `audit_resubmit_cap`
  for clarity. Skipped to avoid gratuitous churn.
